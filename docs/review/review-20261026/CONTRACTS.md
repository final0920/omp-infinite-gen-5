# 五项契约逐项审查建议（待所有者确认）

本轮执行者 Codex；以下为技术建议，不替代所有者裁决，也不记录为已确认。工具总数仍为 Core 8 / Full 43，审批门仍为 13，未增删工具或放宽预算。

| 项 | 核对内容与建议 | 必须保留的边界 | 所有者状态 |
|---|---|---|---|
| ig5_package（P3/P6） | 建议接受一个入口承载 apk/firmware/unpack/result；核对 analysis_tools 分派、本地显式路径、解包输出在 artifactDir 内、预算及安全名字处理 | “静态、无目标执行”不等于只读；unpack 写出文件。固件历史仅自造镜像/独立工具对照，没有真实设备固件效果保证；不能把容器识别当恶意结论。未新增长期审批门需要所有者确认这类受限写出的契约 | 待确认 |
| P7：ig5_scan rules/max_rule_matches | 建议接受参数增量；rules 为替换内置表的受限语法，UTF-8 最多 65,536 字节、规则/字符串/节点/匹配数有界，省略 rules 仍走内置表，非法构造拒绝 | 不等同完整 YARA；签名结果是线索，不证明行为/身份；误报漏报未知，不支持的构造不得静默接受 | 待确认 |
| P8：ig5_dbg apitrace | 建议限已审批、已持有并暂停的本地原生 x64dbg 进程接受；核对公共参数、暂停前置、后端限制、继续运行状态、限额、报告保存及失败回执。两个过期关键文件的增量均与此相关 | 会继续执行目标并设置软件断点，不能称静态；仅主镜像静态导入且已解析 IAT，参数是原始入口值；有范围/清理状态，无意图或完整覆盖保证；客体与未实测架构不外推 | 待确认 |
| P9：ig5_capture correlate/sample | 建议在本轮截断漏报修复及回归基础上接受；只比较已保存记录与 32 MiB 内本地文件，稳定读取及可选哈希；无监听、请求或目标执行 | E1 为捕获字节同一性，E0 为字面量存在；文件偏移不是 RVA，匹配不证明运行时使用。每条/全局匹配限额现均报告截断；尚无真实业务流量/样本验证 | 待确认 |
| P2：workspace/recovery 拆分 | 建议接受拆分；Core 8 不变，Full 41→43，profile 旧参数明确指向新工具；核对注册、作用域、任务队列及原处理器复用 | workspace 可更新任务存储，recovery 写不可变报告，不能称只读；workspace list 要求显式已打开的静态目标；Core 体积是字符数/4估算，不能当指定 tokenizer 实测 | 待确认 |
