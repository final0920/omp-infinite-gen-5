# LCM 与逆向长任务：从第一性原理到验收

日期：2026-10-21。实现研究基线：lossless-claude/lcm
`0c17dbffda452cf7fae46929af427dff355aeaa3`（0.16.0）。
本文先于集成实现建立论证；它不是“模型准确率已提高”的实验报告。

## 1. 问题与已有基础

逆向任务的输入包括目标字节、工具结果、运行时状态和人/模型作出的假设。
有限上下文不能永久容纳无限增长的历史。DSH 已有持久事件日志；IG5 已有
SHA 绑定报告、dossier、revision/epoch 与 stale 标记。因此缺口不是单纯没有磁盘，
而是压缩后缺少低成本、带身份的导航与精确回取，并可能把摘要当成证据。

原始程序状态不等于会话事件：工具输出前已截断的数据、未采集的内存、隐藏推理、
外部文件后续改写，都不能由保存聊天补回。本文的无损边界是实际接收并确认提交的
JSON 事件，按固定序列化后的字节定义；不是原始网络 JSON 的空白或对象键顺序。

## 2. 为什么不能证明一个短摘要普遍无损

设历史 H 有 N 位，摘要 S 至多 B 位，N>B。可取的历史多于摘要，鸽巢原理保证
至少两个不同历史得到同一摘要。选择一个答案在这两个历史中不同的问题，任何仅依赖
S 的回答器都不能对两者同时保证正确。除非任务分布受限且摘要是该任务的充分统计量，
“摘要保留全部未来所需事实”无法普遍成立。多轮摘要不会恢复先前已经丢失的区分。

LCM 改变的是系统可访问信息：保存 H，S 只作索引，并允许按引用读取 H 的片段。
原文可回取不等于查询一定命中，更不等于模型能正确推理。原论文也明确不保证模型
总会导航到需要的原文：https://papers.voltropy.com/LCM ，第 2 节。

## 3. 可以条件证明的性质

假设：事件提交使用事务；已提交原文不可被摘要覆盖；引用携带会话身份和摘要；
读取校验失败显式报错；底层文件系统/SQLite 按其持久性合同工作；攻击者不能同时
修改数据和全部校验根。SHA 抗碰撞是工程假设，不是数学上绝不碰撞的证明。

**P1 原文保留。** 初态没有事件。追加只新增事件，重复的相同身份/字节幂等，
同身份不同字节拒绝。压缩只新增派生节点和来源边。因此对操作次数归纳，任一成功
提交的原始事件在任意次压缩后保持不变。磁盘损坏/删除在此假设外，检测不能修复备份。

**P2 有限可恢复。** 对来源完整的节点，叶摘要指向原始消息，合并摘要仅指向已有节点，禁止跨会话和
向未来引用，所以图无环。按深度归纳，每个派生节点都可追溯到原始事件。将有限事件
分页，按单调 offset 读取并核对同一 hash，可在有限次请求后重组原文。预算不足时
必须返回下一游标/未完成，不能报告完整交付。宿主未提供或未捕获的来源明确标缺失；
一层来源完整不代表全部祖先完整，必须递归核验。

**P3 隔离。** 存储由可信的 DSH session id 与 workspace 共同绑定；公开查询不接受
任意其他 session id。相同地址/寄存器名称不能合并两个会话或运行。原文保留报告的
target SHA、run/thread/epoch、revision；历史观察不会自动成为当前运行态证据。

**P4 工作集有界。** 恢复包只返回有限引用，搜索返回有限条目，精确读取每页最多2048个
UTF-16单元且不切开代理对，检查点文本另有UTF-8字节上限。这能证明接口输出有界，
不等于模型 token 总预算；后者还受 tokenizer、工具 schema、
DSH 历史与系统提示影响，必须由宿主计数。不能宣称接入插件就取消了宿主压缩。
512MiB配额是序列化载荷配额；SQLite页、索引和WAL另占磁盘，不能称为物理磁盘硬上限。

**P5 语义不升级。** 模型/宿主摘要始终是未经独立验证的导航材料。SHA 仅验证保存内容
身份，不能证明摘要真实；恢复不授予样本执行权限、不复用旧审批、不提升业务通过状态。

## 4. 哪些收益可以推导，哪些必须测量

若忽略检索成本，并允许最优策略忽略额外记忆，(S,H可查询) 的策略空间包含仅用 S
的策略空间，所以最优可达准确率不会降低。这是可达上界结论，不是实际 LLM 的单调性
保证。真实模型可能检索错误、受旧假设干扰，或花更多时间。

用期望成本定义是否值得：J = C模型 + C存储检索 + C等待 + L错误 * P错误。
在同一任务分布和相同验收下，只有 J_LCM < J_基线才是净收益。工程先验是：精确数据
多、任务跨越多次压缩、重采集昂贵时，按需回取更有机会节省成本。若上下文很短或答案
已经在当前窗口，记忆可能只有开销。因此采用懒启动、有限恢复，不先全量重读所有历史。

## 5. 上游取舍与集成边界

上游完整源码和 Git 历史独立保存；发行物保留固定源码档案、MIT 许可、来源清单和
可重建的核心 bundle。真正复用上游 ConversationStore、SummaryStore、数据库迁移，
而非把另一套自写存储仅命名为 LCM。

上游通用 capture 会脱敏、规范化文本并截短部分工具输入。逆向精确证据不经过这条
有损采集路径：IG5 用固定 JSON 事件与 SHA 保存本地档案，上游存储作为索引/来源图。
不安装上游全局 hooks，不启动其默认外部摘要 provider，不读取其他产品的历史。

DSH 继续管理压缩与模型调用。IG5 复用已提交的 DSH compaction/summary 构造来源节点，
提供 search/read/expand/restore，并在有原生 runtime-context 能力的会话恢复导航。
这属于 LCM 存储/检索核心的 DSH 适配，不是上游全部 CLI、daemon、promoted memory 或
自动 LLM 压缩器原封不动运行。单独检查已安装宿主 API，源码存在不能代替实际兼容。

## 6. 验收与可证伪条件

结构验收必须覆盖：多次压缩后精确内容恢复；相同事件重放幂等；同 ID 冲突拒绝；
不同会话隔离；摘要失败不损伤原文；中文/NUL/64位地址；大事件分页；磁盘重开；
限额和缺件显式反馈；真实 DSH SDK 事件与 runtime-context 接入。数据库测试不能冒充
真实模型逆向成功。

成本试验使用固定历史的同一查询集，比较摘要-only与摘要+原文回取。报告丢失的条件、
找回的精确字节、输出量、读写耗时；确定性查找试验只证明检索管线。
真实模型试验还须固定模型、预算、目标与独立答案，按多个任务/重复次数比较准确率、
重复取证、输入/输出 token 和总耗时，并保留失败。若检索收益不足抵消开销，拒绝把
它作为默认全局机制；若无法回取反例/前提，停止宣称适合高精度逆向。

结论：第一性原理支持“保留原文+可追溯摘要+有界精确回取”作为值得实证的方案，
能够排除仅靠摘要无法避免的信息不可逆丢失。它不构成通用智能提升或业务恢复保证。
