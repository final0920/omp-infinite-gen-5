# 无限五代：逆向工具架构蓝图

状态：设计稿，2026-10-24（v2，取代此前把"案件/证据链"放进工具里的 v1，那个方向是错的）。编制：AI 代理，需由熟悉场景的人复核。
宿主：只有 DeepSeek Harness（DSH）。

## 0. 定位（先把边界说清楚）

**无限五代是逆向工具，卖给做取证与分析的客户使用。**

- 工具负责：把样本**逆得更深、更准、更完整**，并让结果**可被引用**。
- 工具不负责：案件、授权、鉴定、报告格式、法律与出证流程——这些是客户的事。
- "可被引用"在工具侧的含义只有三条：**每条结果带来源锚点**（哪个文件、哪个位置、哪个版本的工具产生）、**可复现**（同样输入同样结果）、**标明验证到什么程度**（见 §3.3）。

## 1. 客户要分析的对象，和工具要能回答的问题

| 对象 | 工具要能回答（能力问题，不是流程问题） |
| :--- | :--- |
| 恶意样本 | 它对系统做了什么；怎么驻留；与谁通信；有无加密/混淆/反分析；配置在哪 |
| APK | 权限与组件；DEX 里的类/方法/字符串；动态加载；原生库做了什么 |
| ELF | 架构与加载；特权与系统调用；共享库与持久化位置 |
| 固件 | 容器与文件系统；组件清单；可执行体入口；异常服务/硬编码凭据 |
| 加壳/保护 | 是什么壳；还原到哪一步；**哪些没还原** |
| 流量 | 会话与协议；载荷内容；与样本中的通信逻辑如何对应 |
| 外挂 | 读写了哪个进程的哪些数据；用什么方式拿输入；是否有驱动组件；是否对抗检测 |

## 2. 现状（据代码实测，非印象）

已有：Ghidra 静态（函数/字符串/交叉引用/反编译/CFG/栈/switch/vtable/导入导出）、x64dbg 调试、Unicorn 单函数仿真、抓包代理与协议推断、加密常量与熵扫描、微码级去混淆（有界）、版本差异比对。

缺口（据 40 个工具逐个核对）：
| 缺口 | 现状 |
| :--- | :--- |
| 行为清单 | `ig5_scan` 只分 8 类、约 100 个 API，不含 `ReadProcessMemory`/`OpenProcess`、服务/驱动、驻留、令牌提权、键鼠/屏幕采集、反虚拟机、文件破坏、Linux/Android 系统调用等；**不按函数聚合、不识别"行为链"** |
| 动态解析的 API | 恶意样本常用字符串+`GetProcAddress` 隐藏导入，目前不会从字符串里识别 |
| APK/DEX | 零 |
| 固件 | 零 |
| 特征规则匹配 | 零 |
| 加壳识别/自动脱壳 | 只有熵提示；脱壳仅在自产样本上验证 |
| 字符串/配置自动解码 | 有 XOR/AES 变换与有界恢复，**没有"找到解码例程并批量仿真解码"** |
| 动态行为轨迹 | 有调试器，没有 API 级轨迹与行为汇总 |
| 流量 ↔ 样本对应 | 有采集与协议推断,没有把一条交换与一个样本文件做证据化对照 |
| 工具面体积 | Core 8 曾 ≈ 1.3 万 token（`ig5_profile` 占 81%）；**P2 后 3,478/4,000 估算 token**（字符数/4），最大单工具 `ig5_workspace` |

## 3. 架构原则

### 3.1 分层
```
DSH ── 工具面（少而稳，渐进披露）
   │
   ├─ 分析编排（pass 流水线：按目标类型选 pass，pass 之间只通过 Fact 通信）
   │     行为清单 · 字符串/配置解码 · 加壳识别 · 协议/流量 · 加密例程 · 差异比对
   │
   ├─ 验证层（独立于生成 pass：仿真 / 差分 / 回放 / 求解）→ 给 Fact 打验证等级
   │
   ├─ Fact 层（带锚点的结构化结果：种类、位置、数据、产生者@版本、输入摘要、验证等级）
   │
   ├─ 前端（把不同格式归一成统一的分析对象）
   │     PE/ELF/Mach-O（经 Ghidra） · APK/DEX（新） · 固件容器（新） · PCAP · 原始字节
   │
   └─ 引擎适配（Ghidra · x64dbg · Unicorn · 客体虚拟机）每会话隔离的工作进程
```
依赖只允许自上而下；验证层不依赖生成 pass 的内部状态。

### 3.2 设计规则
1. **pass 化**：每种分析是一个有明确输入、输出 Fact、预算和失败语义的 pass；新增能力 = 新增 pass，不是改一个巨型工具。
2. **数据驱动的规则表**：API 分类、特征、行为链放在可单独审查和更新的数据文件里，不埋在逻辑中。
3. **输出必须带锚点和覆盖度**：每个 Fact 有来源位置；每个 pass 报告"分析了多少、截断了多少"。
4. **工具面最小**：默认暴露少量轻量工具，其余按需披露；一个工具一个意图。
5. **失败默认关闭，未知保持未知**（沿用现有纪律）。
6. **新增代码必须小、可审查、有针对性测试，并登记进人工审查台账**。

### 3.3 结果的验证等级
对"这段代码做了什么"这类语义结论，结果里标明级别，不用"完全还原"这类措辞：

| 级别 | 含义 |
| :-: | :--- |
| E0 | 仅静态阅读/规则匹配得出 |
| E1 | 与一次记录的执行一致 |
| E2 | 对一组输入的差分仿真一致 |
| E3 | 对有界路径形式化证明 |
| E4 | 整个函数域证明（少见） |

## 4. 能力路线（按价值、可测性、风险排序）

| # | 能力 | 类型 | 说明 | 可测性 |
| :-: | :--- | :--- | :--- | :--- |
| P1 | **行为清单**：扩展 API 分类表；按函数聚合；识别行为链（如 进程访问→远程写入→远程线程）；从字符串识别动态解析的 API | pass + 规则表 | 打开样本后一次调用给出"它能对系统做什么、证据在哪些函数"。改动集中在 `scan_analysis` 与 Ghidra provider，**不新增工具** | 纯 Python 单测 + 真实 Ghidra 夹具 |
| P2 | **工具面瘦身**：拆分 `ig5_profile`，Core ≤ 4k token | 架构 | 40 个工具契约变更需评审 | 体积脚本进 CI |
| P3 | **APK/DEX 前端**：清单与权限、组件、DEX 类/方法/字符串表、原生库清单 | 前端 | 标准库实现，输出统一 Fact | 自造 APK 夹具 |
| P4 | **字符串/配置解码**：定位解码例程 → 仿真批量解码 → 回写为注释/Fact（验证等级 E1/E2） | pass + 验证 | Unicorn 已在 | 自造夹具 |
| P5 | **加壳识别与脱壳状态**：节异常、入口特征、壳签名；明确"已还原/部分/未还原" | pass | 不外推自产样本结论 | 自造夹具 |
| P6 | **固件前端**：容器与文件系统识别、递归解包、组件清单 | 前端 | | 自造镜像夹具 |
| P7 | **特征规则匹配**（YARA 风格规则的受限子集）：内置壳/保护器/安装器/运行时规则表 + 调用方规则源，结果并入 `ig5_scan` | pass + 规则表 | **不新增工具**；`ig5_scan` 新增可选参数 `rules` / `max_rule_matches`（参数增量，随评审） | 规则单测 + 真实文件 + 真实 Ghidra 验收 |
| P8 | **动态 API 轨迹与行为汇总**:在已接管并暂停的原生进程上对导入 API 入口设断点,记录调用顺序/入口参数/返回地址,归并为行为类别与线程内行为链(`ig5_dbg` 的 `op=apitrace`) | 执行层 | 复用现有 x64dbg 调试与审批门 | 自造 PE 夹具的原生运行态 + 离线单测 |
| P9 | **流量 ↔ 样本通信逻辑对应**:把一条已保存的交换与本地样本文件做只读对照——正文哈希同一性(E1)与端点/请求头值/网络 API 字面量及文件偏移(E0)(`ig5_capture` 的 `action=correlate`) | pass | 不新增工具;纯静态字节对照,不执行、不开引擎、不发请求 | 纯 Node 单测 + 真实回环代理下发运行态 |

垂直研究（`vm_*`、CFF、位向量）定位为**可选的验证/还原扩展**，不占默认路径。

## 5. 与现有代码的关系
- `worker/scan_analysis.py` 是 P1 的落点（引擎无关、读取器注入、已有预算与截断语义），沿用它的结构。
- `adapters/ghidra/worker.py` 的 `m_scan` 负责向 `scan_analysis` 提供导入、引用与函数归属。
- 商业 IDA 分支可删除；IDA 兼容层（`ig5_run_idapython`、`script_api`）保留。
- 工具契约（40 个、13 个审批门）变更需评审，P1 不改契约。
