# 证据与停止判断

持久目标应写用户真正要求的结果；不要把“完整逆向 VMP 3.8”改成“加载样本并输出一段伪代码”。可按目标拆分里程碑，但最终完成仍需要全部要求有对应证据。记录中区分未测、来源已核验、只读装载、真实动态采集、局部语义、受测业务模型和整个原程序。

每项验收引用本轮保存的报告路径/UUID与摘要，受测源码/安装版本、输入样本 SHA、目标/运行/线程/暂停身份、环境改动和实际边界。复用旧轨迹作新只读重放时分别保留原生采集与新重放来源；不能把重放说成重新执行了目标。核对完整报告，工具预览省略证书数组不代表证据不存在。

本轮未读取的历史证据标为未复核，不能据此宣称整个项目“零证据”或“尚未开始”。旧失败与后续修复分别保留；发现新 receipt 时先核对来源与时间再更新判断。退出码按具体工具契约解释，不能把所有非零一律视作失败：维护侧 Robocopy 的 0–7 属成功范围，仍须另核对实际文件摘要；这不改变分析器自身的成功判定。

数学恢复须保留全部输入位宽与自由变量，接受的改写有局部 SMT UNSAT、定义展开/父项同余与最终投影证书。独立作者/自产源码公式只在恢复后验证，不作为恢复输入。有限测试对照不等于全输入域证明。路径守卫、互斥/覆盖、未解环境和副作用分别报告，`wholeBinaryVerified=false` 不能在最终回答中升级为全程序恢复。

已知典型失败：Enigma 八轮的输出表达式可证明，但记录内部分支/地址条件存在不覆盖全部输入的反例；证明输出代数与源码相同仍不证明这些未记录分支。VMP Ultra 八轮在指令预算内没有返回，不能以已通过的 Ultra 分支案例替代。3.11 的自产验收不能自动证实一个具体 3.8 构建或所有保护配置。

每轮先检查是否有可验证的新状态。工具/进程仍存活时观察原 handle，不能因一次超时而重启；明确终态后再决定修复或新实验。改变假设、修复代码、增加独立证据或定位反例属于进展，重复状态说明不属于进展。保存 next_step、失败分类和所需数据，恢复后从当前证据继续。

原生断点验收分别核对安装确认与真实事件/RIP；`bpt` 响应中的地址是所请求的断点位置，不表示程序已停在那里。硬件断点可在同 run/thread/stop 下读取实际 DR 地址与使能位；它只证明该暂停时已装入所读线程，后续命中仍须事件及实际寄存器。读取实际入口实参和 RSP 上的返回地址，核对本次模块映射，再验证真实返回暂停及输出。进程退出不能替代函数返回；停止请求之后的退出事件，即使退出码为零，也不证明程序自然完成。自产程序若通过 `ExitProcess((UINT)result)` 传结果，非零退出码可为正常数据，低32位匹配也不能证明完整64位返回或业务恢复。

等待原生事件时，普通 Demo/应用提示可能阻塞执行。记录已观察的交互与进程状态，使用当前任务允许的正常交互后复查同一运行；没有交互能力时保留等待状态，不能猜测提示已确认、入口不可达或保护器异常。交互变化和后续命中是相关证据，不足以断言此前所有超时/退出具有同一原因。正常提示的确认不意味着可处理系统安全请求或修改许可。

Skill、模拟测试、schema/SDK 注册通过和最终文字均不足以证明自主闭环。真实闭环验收至少观察：人类任务触发宿主 Goal；本轮产生证据后即使回答结束，自动 Goal Round 被接纳并继续工具调用；结果和状态持久保存；失败触发有证据的新策略；完成要求未满足时不报 complete；停止/取消不自动复活。样本本身的业务恢复验收还需单独完成。
