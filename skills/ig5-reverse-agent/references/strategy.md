# 研究与引擎选择

优先解决当前证据指向的失败。每种保护器分别记录版本、位宽、保护选项、输入与生产器/附件来源、样本 SHA 和测试日期；一家的通过不外推另一家，同一家基础选项不外推 Ultra、其他 VM 或 RISC。PE/ELF、x86/x64/ARM64 与 managed/Dex 使用不同装载与执行模型，按 `ig5_doctor` / `ig5_profile` 的实际 capabilities 选择；有 CPU 仿真不代表有完整 OS、驱动或移动端运行环境。

| 当前问题 | 下一步证据 | 不足以通过的结果 |
|---|---|---|
| 压缩/加密代码 | 页级来源、运行时映射、首次可读代码、目标 hash 不变 | 内存 dump 或 OEP 猜测 |
| 导入或加载器 | 实际调用目标、模块归属、重定位与异常状态 | 人工生成的 IAT 名单 |
| 调试器异常/线程 | 同 run/thread/stop 的事件、退出与清理确认 | 命令已接受、旧通知、线程隐藏猜测 |
| 共享 VM 表达式 | 位宽、符号依赖、局部等价与投影证书 | 当前输入拟合出的公式 |
| VM 内部控制流 | 全部原约束、反例、其他路径及互斥/覆盖 | 一条轨迹的输出等价 |
| VMP 3.8+ handler | 真实入口、VIP/VSP/key 数据流、合并 handler 的状态转移 | 沿用旧版本 opcode 表或固定 GPR |

VMP 3.8+ 优先研究合并 handler、滚动解码密钥、VIP/VSP 的寄存器迁移以及 handler 间状态。先由实际轨迹和 SSA 追踪读写，再尝试局部提升；保留内存、flags、间接分支与环境依赖，不能因目标代码暂时看似纯计算就删除。

已有派发观察但全函数提升停滞时，按 [handler 语义与组合边界](handler-semantics.md) 提取有范围的状态摘要。研究原型与公共工具能力分别记录；对投影的证明不能代替后继 scratch/flags 活性、表写入失效或函数业务证明。

原文件中的 AMD64 函数可显式尝试 `ig5_ir level=lift target=<绝对路径> ea=<首选VA> initial_flags=<0x0..0xfff>`，需要时传最多16个已确认的 `lift_inline` 地址与 `max_blocks`（默认512，最多4096）。这是固定开源 Mergen 的只读实验后端，不执行目标、不打开数据库；不用 action、max_instructions 或 trace 参数。初始 flags 仅低12位模型，不自动绑定原生录制，也不代表完整架构标志语义。运行时不可用就记录缺件，不改用任意下载的可执行文件。

先检查 `process`、`diagnosticsSummary.unresolved`、`liftStats` 和完整报告引用，再决定后续。进程正常退出或生成 LLVM IR 不表示业务恢复；该入口始终 `partial/unverified`，不会自动增加通过数。符号返回地址、未决内存或控制流必须结合录制状态、独立语义证明和覆盖继续定位；不能删除警告、把观察地址写成常量或把原生映像冒充原文件。完整 IR/诊断按 `outputRefs` 与 `reportPath/reportSha256` 核验。

候选地址集合可能因未知分支、循环或预算而不完整，未匹配地址必须保留原始读取，不能用首个候选值兜底。静态候选与其完整性是不同证据；单候选不能自动视为唯一可能控制目标。`blocks_completed` 为后端finished状态计数，并非全部提升块完成数；它与attempted/unreachable不构成互斥分区或覆盖证明。诊断警告后工作队列可能仍继续，须查看最终IR的真实缺口。

完整有限地址读取的认证仅接受不可变参数／常量整数DAG及全覆盖的当前候选值；PHI、内存依赖、归一化或未知写入均不能借此消除读取回退。两份64轮诊断已能在原512块内返回RCX+96，其完整返回SSA已独立证明；该结果不证明普通内存副作用、全优化管线或Ultra循环状态恢复。继续遇到211时核对地址集合是否被独立认证，以及派发条件是否跨迭代保留；不能仅凭枚举到了几个地址就删除默认分支。

诊断411表示未知写入使后续映像／buffer读取折叠失效。核对写入指令、地址SSA、可能别名范围及当前原文件／录制来源，保留真实LOAD和未知控制续程。只有证明写入与所用代码、表或字节码不相交后，才能研究恢复局部常量；文件RX或记录中未出现覆盖不构成该证明。未知返回、更早停止或exit0均不计业务通过；不同路径可能因保守失效而丢失精度。

诊断211表示控制目标集合仍不完整。检查原始目标表达式、已枚举的raw地址和默认分支；`__ig5_unresolved_control_*` 保留未知转移及返回值，不能把它的参数当业务返回。预算诊断503及 `__ig5_unlifted_block_*` 表示尚未提升的续程，后者参数是分析块标识，不是原生地址。下一步根据目标依赖或状态合流定位缺口，并在相同预算下做回归；不要重复同一命令、删除默认分支或把未知返回拟合为常量。数值目标域完整也不证明内存、调用、副作用和函数业务完整。

函数入口标记（包括PE异常展开表）不证明寄存器或内存状态相同。多次进入同一地址时核对各来源的状态及合流依据，不能因“这是一个函数”就复用先前路径的返回值。已有自产三目标循环复现RCX=1应返回32却错误返回47；先修复为未知续程，再通过保存可证明的输入条件完成这两份16轮夹具的返回SSA验证。此结果不代表其他循环、VM内存状态或保护器业务已经恢复。

多目标分支仅在目标相等确实排除另一选择臂时保存选择条件；未知臂可能等于已知目标时不选择已知臂。原始地址别名共享队列状态，只保留所有别名共有的条件，父块／默认分支不继承边条件。跨指令复用仅限完整依赖为函数参数／常量的纯整数Boolean表达式；PHI、LOAD、CALL、freeze、poison／undef及特殊溢出承诺拒绝，不能冻结VM游标或录制观察值。每阶段128访问／16层，匹配最多64条保存条件；既有块／求解／进程预算不扩大。即使IR保留opaque默认分支，完整守卫的UNSAT也可能证明该分支不可达；必须核对绑定同一完整模块的证明，不能仅凭标记有无判断恢复。

当 `guard=null` 时读取 `guardDomainDiagnostic`。`not-universal` 的SAT witness可作为下一次已授权动态试验的候选输入；固定目标与原编译／样本证明，核对真实分支、返回与新轨迹，再离线重放。求解反例本身不证明已执行另一条路径。`unknown` 保留拒绝原因；`universal-under-fixed-environment` 也仅为该记录的固定环境诊断，不能代替覆盖验收。预览截断时按 reportPath/SHA读取完整 attempts／provedRanges。

原文件不可用但已有录制映像时，可显式使用 `ig5_ir level=trace trace_image_only=true trace_target_sha256=<录制目标摘要>`。target须为报告中的绝对路径标签，每条路径提供匹配的trace_image／recording；只读取已有数据，不恢复／改名被隔离的原文件。检查 `targetVerification` 与原文件比较项的null，不把录制身份当成原文件新验真。记录前缀与完整返回分别报告，即便前缀输出证明UNSAT也不能宣称函数业务已恢复。

区分证书用途：`guardCandidateSearch.attempts` 中的SAT用于否定某个候选，`rejectedByWitness` 仅复用该反例来拒绝其他候选；它们不表示输出公式已被反驳。输出、最终守卫等价和覆盖证明各看各自的查询与范围，不能统计全报告SAT/UNSAT数量来决定业务是否通过。

可参考的原始资料（2026-10-15 核对；来源声明不等于五代验收）：

- [REcon 2024 VMP 3.8 研究](https://www.recon.cx/cfp.recon.cx/recon2024/talk/YQK3FK/index.html)：现代 handler 与解码状态研究入口。
- [Mergen](https://github.com/NaC-L/Mergen)：汇编到 LLVM IR、函数层面的提升与优化。作者示例包含 3.8.1 Ultra，且说明其余保护选项关闭；GPL-3.0。学习其控制流/内存语义和回归方法，不能把示例覆盖说成所有选项通过。
- [VMProtect-devirtualization](https://github.com/JonathanSalwan/VMProtect-devirtualization)：作者的轨迹、符号执行和LLVM研究；示例重点为纯函数。借鉴输出切片与语义验证，保留路径条件、环境与内存依赖；示例恢复不能外推带副作用的任意程序。
- [VMPLift](https://github.com/sexyiam/VMPLift)：作者声明面向 3.8–3.10+ x64 的 handler/VIP 追踪；MIT。五代此前源码审阅发现未知状态填零与探针拟合风险，须独立核验，不能原样采纳结果为证明。
- [TritonDSE](https://github.com/quarkslab/tritondse)：Triton 上的装载、动态符号执行与探索；作者当前明确支持 ELF/Linux。借鉴路径调度与输入生成，不把它说成已验证 Windows PE 引擎；五代的固定 Triton、实际内存观察和预算不能因采用探索算法而失效。
- [QSynthesis](https://github.com/quarkslab/qsynthesis)：Triton 位向量表达式的灰盒合成与 SMT 等价检查；实验项目、AGPL-3.0。可研究候选表达式搜索与验证方法，当前未安装或集成；有限 I/O 拟合不能代替完整符号等价证明。
- [Titan](https://github.com/archercreat/titan) / [NoVmp](https://github.com/can1357/NoVmp)：旧版本去虚拟化参考。适用范围分别由作者限制在 3.8 之前、3.0–3.5，不能作为 3.8 通过证据。
